PDFDancer v3 Is Here: Precise Text Editing, Production-Grade Reflow

We're excited to finally share PDFDancer v3. We've rebuilt how PDFDancer works with text, from precise editing to production-grade reflow. V3 also introduces semantic reading units, so you can work with a document's structure as well as its text.

Explore API v3

Precise control over PDF text

This is a big step beyond line- and paragraph-based editing. Target content, style runs, anchor carets, regions, or coordinates, then replace, insert, delete, or restyle exactly what you need.

For example, this finds style runs by font, size, and content, then changes only those matches: 

from pdfdancer import PdfColorRequest, TextStyleRequest

response = pdf.page(1).text().style(
    TextStyleRequest.runs_where()
    .where_font("Helvetica-Bold")
    .where_size(12, tolerance=0.25)
    .where_text_contains("Total")
    .font("Helvetica")
    .fill_color(PdfColorRequest.rgb(0, 0, 0))
    .build()
)

A production-grade reflow engine

We're especially proud of the new reflow engine. The previous engine wasn't ready for production; this one handles paragraphs, columns, lists, tables, headings, code, justified text, and explicit whitespace.

You decide whether to preserve source positions, keep existing line breaks, or require full reflow. The response tells you what actually happened.

This replacement requires body-text reflow, turns off generated hyphenation, and rejects an incomplete result: 

from pdfdancer import TextLayoutProfile, TextReplaceRequest

response = pdf.text().replace(
    TextReplaceRequest.literal("Q1", "First quarter")
    .whole_words(True)
    .pages(2, 4)
    .max_matches(2)
    .require_reflow(TextLayoutProfile.BODY_TEXT)
    .hyphenation_enabled(False)
    .build()
)

if response.errors or response.matched != response.changed:
    raise RuntimeError(f"Text edit was incomplete: {response.errors}")

for change in response.change or ():
    print(change.page, change.applied_layout_mode)

Structured text extraction

V3 also opens up a new way to read PDFs in code. Reading units classify headings, paragraphs, lists, captions, footnotes, and other semantic blocks, with reading order, source provenance, page bounds, and relationships.

One call analyzes the complete document: 

analysis = pdf.analyze_reading_units()

The Python SDK maps the response to typed ReadingUnit objects. Here's the underlying API data for one abridged unit: 

{
  "id": "unit-1",
  "role": "HEADING",
  "text": "Quarterly results",
  "stream": {
    "PRIMARY": {"included": true, "order": 1}
  },
  "provenance": {
    "pageNumber": 1,
    "sourceElementIds": ["text-17"],
    "bounds": {"x": 72, "y": 680, "width": 214, "height": 18}
  },
  "relationships": [
    {"type": "HEADING_PARENT_OF", "targetUnitId": "unit-2"}
  ]
}
